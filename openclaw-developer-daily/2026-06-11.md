**[#91720](https://github.com/openclaw/openclaw/pull/91720) fix(openai): remove chatgpt-responses transport override from gpt-5.3-codex catalog entry** 🔴 P1
- **Author**: @a-tokyo
- **Labels**: `P1`, `merge-risk: 🚨 auth-provider`
- **Merged**: 2026-06-10 23:42 UTC

**关键修复**：`gpt-5.3-codex` 的静态 catalog 条目硬编码了 `openai-chatgpt-responses` 传输层和 `chatgpt.com/backend-api`，导致使用标准 OpenAI API Key 的用户完全无法使用该模型。移除传输覆盖后，模型继承提供商默认的 `openai-responses` + `api.openai.com/v1`，恢复 v2026.5.18 行为。OAuth/Codex 用户不受影响（动态模型解析独立处理路由）。

**[#91711](https://github.com/openclaw/openclaw/pull/91711) fix(agents): classify harness provider mismatch as format error**
- **Author**: @a-tokyo
- **Labels**: `agents`, `P2`
- **Merged**: 2026-06-10 23:40 UTC

当 agent harness 因提供商 ID 不在支持集中而拒绝模型时，错误之前被归类为 `unknown`，导致用户在模型回退通知中看到无意义的信息。现在将 harness 拒绝消息归类为 `format` 错误，使回退通知更加可操作。

**[#91696](https://github.com/openclaw/openclaw/pull/91696) fix(agents): preserve reasoning_content replay for Gemma 4 openai-completions models**

修复 Gemma 4 模型通过 openai-completions（vLLM、OpenRouter 等）使用时，多轮工具调用回放中 `reasoning_content` 被静默丢弃的问题。这导致工具调用质量严重下降（参数坍缩为 `{}`、重复调用同一工具）。移除了两处对 Gemma 4 的推理内容排除逻辑。

**[#91688](https://github.com/openclaw/openclaw/pull/91688) fix(cron): reject cron expressions that have no reachable run time**
- **Author**: @yetval
- **Labels**: `gateway`, `P2`
- **Merged**: 2026-06-10 17:39 UTC

结构合法但永远无法匹配任何时间点的 cron 表达式（如 `0 0 30 2 *` 代表"2月30日"）之前被静默接受，创建的定时任务永远不会触发、不出现在运行日志中、也不会自动禁用。现在在服务层验证边界添加可满足性断言，`cron.add`/`cron.update` 会拒绝这类表达式并返回 `INVALID_REQUEST`。

**[#91614](https://github.com/openclaw/openclaw/pull/91614) fix(gateway): surface headless LaunchAgent state**
- **Author**: @fuller-stack-dev
- **Labels**: `gateway`, `cli`, `P2`
- **Merged**: 2026-06-10 05:21 UTC

macOS 上当 LaunchAgent 已安装但处于无头（headless）状态（无 GUI 会话）时，`gateway restart` 的恢复流程会错误地降级到非托管进程重启。现在将 `gui/$UID` bootstrap 失败分类为独立的 `missingGuiSession` 状态，`gateway status` 和 `doctor` 提示也会优先说明 GUI 会话要求。
