## 头条深度

### OpenAI 前沿模型与 Codex 全面登陆 AWS：AI 基础设施分发进入"云原生"阶段

**事件**：OpenAI 6 月 1 日宣布 [OpenAI frontier models and Codex are now available on AWS](https://openai.com/index/openai-frontier-models-and-codex-are-now-available-on-aws/)。这意味着数百万 AWS 客户可以通过他们已有的安全、合规、采购、计费和治理工作流，直接在 AWS 环境中使用 OpenAI 前沿模型和 Codex 软件工程 Agent。Codex 通过 Amazon Bedrock 提供服务，同时开放 Commercial 和 GovCloud 区域。

**为什么它值得做头条**：过去两年，企业采用前沿 AI 的最大瓶颈不是模型能力，而是把模型塞进现有安全审查、合规流程、采购审批和生产部署管道的成本和时间。OpenAI 把前沿能力直接放在 AWS 上，意味着企业不再需要单独和 OpenAI 签约、单独审计、单独搭建集成——一切都走 AWS 已有的通道。这不是技术突破，但可能是 2026 年企业 AI 分发最重要的单步。

**关键信息**：

- Codex on Amazon Bedrock 将 OpenAI 每周超过 500 万用户使用的软件工程 Agent 带入 AWS 环境，帮助团队在已有构建和交付环境里写代码、审查、调试和现代化。
- 客户可以利用 AWS 现有的安全、治理和运营框架来部署 OpenAI 能力，减少从评估到生产的摩擦。
- OpenAI 预告 Daybreak 的未来可用性——包含网络安全模型和 Codex Security，旨在帮助安全团队更早发现风险、更快行动、让软件更具韧性。Daybreak 将把安全代码审查、威胁建模、补丁验证、依赖风险分析、检测和修复指导整合到日常开发循环中。

**深度分析**：

这件事的意义需要放在更大的棋局里看。OpenAI 已经有了 Azure 的分发通道（通过 Microsoft 合作），现在又加上了 AWS。两个最大的公有云都成了 OpenAI 的分发管道。当 Anthropic 通过 Amazon（投资 + Bedrock 托管 Claude）和 Google（TPU 容量）建立算力供应链，OpenAI 则在同时建立多云分发网络。

更重要的是 Daybreak 的预告。安全代码审查、威胁建模、补丁验证——这些直接对接 Anthropic 的 Project Glasswing 正在做的事（用 AI 找漏洞和修补关键软件）。两家公司从不同角度逼近同一个问题：AI 不仅能写代码，还能审计代码、发现漏洞、生成补丁。2026 年下半年的竞争重心可能从"谁的模型更强"转向"谁的 Agent 更能深入企业开发和安全工作流"。

## Anthropic

### Project Glasswing 首月更新：AI 发现逾万高危漏洞，瓶颈已是人力而非发现

Anthropic 5 月 22 日发布 [Project Glasswing: An initial update](https://www.anthropic.com/research/glasswing-initial-update)，披露了与约 50 家合作伙伴使用 Claude Mythos Preview 扫描关键软件的首月成果。

**核心数据**：

- 合作伙伴合计发现超过 10,000 个高危或严重级别漏洞。
- Cloudflare 在其关键路径系统中发现 2,000 个 bug（其中 400 个为高/严重级别），误报率优于人类测试者。
- Mozilla 在 Firefox 150 中利用 Mythos Preview 发现并修复了 271 个漏洞——是此前使用 Claude Opus 4.6 在 Firefox 148 中发现的 10 倍以上。
- Anthropic 对超过 1,000 个开源项目进行扫描，Mythos Preview 预估发现 6,202 个高/严重级别漏洞。经 6 家独立安全研究公司评估的 1,752 个样本中，90.6%（1,587）为真实阳性，62.4%（1,094）确认为高/严重级别。
- 典型案例：wolfSSL 加密库中发现可伪造证书的漏洞（CVE-2026-5194），攻击者可利用其伪造银行或邮件服务商的假网站。

**关键洞察**：Anthropic 明确指出，当前瓶颈不再是 AI 发现漏洞的能力，而是人类验证、报告和修补漏洞的速度。一些开源维护者甚至要求 Anthropic 放慢披露速度，因为他们需要更多时间设计补丁。平均一个高/严重级别漏洞需要两周才能修补。这标志着 AI 安全能力已经从"能不能找到"变成"找到太多了，来不及修"。

**链接**：[原文](https://www.anthropic.com/research/glasswing-initial-update)

### Coding Agents 在社会科学：1,260 名研究者的基准调查

Anthropic 5 月 27 日发布 [Coding agents in the social sciences](https://www.anthropic.com/research/coding-agents-social-sciences)，调查了 1,260 名定量社会科学家的 AI 和 coding agent 使用情况。

核心发现：81% 的受访者尝试过 AI 聊天机器人辅助研究，但只有 20% 采用了 coding agents（如 Claude Code）。采用存在显著差异：经济学家采用率最高（39%），公共卫生仅 6%；男性研究者采用率是女性的两倍以上；顶尖大学研究者采用率比其他高校高 40%。Coding agent 用户发布了更多工作论文和基金申请，但尚未看到期刊投稿量的显著增加。

**链接**：[原文](https://www.anthropic.com/research/coding-agents-social-sciences)

## OpenAI

### Rosalind Biodefense：用前沿 AI 加速生物防御

OpenAI 5 月 29 日宣布 [Rosalind Biodefense](https://openai.com/index/strengthening-societal-resilience-with-rosalind-biodefense/) 计划，两个核心动作：

1. **启动 Rosalind Biodefense 项目**：帮助受信任的开发者利用 GPT-Rosalind（前沿生命科学推理模型）构建生物防御和流行病防备应用。首批支持机构包括 Fourth Eon Biosecurity（AI 原生生物安全筛查基础设施）。
2. **扩展 GPT-Rosalind 受信访问**：向部分美国政府及盟友公共卫生和生物防御机构开放。Lawrence Livermore 国家实验室利用 AI 推进生物防备；Johns Hopkins Applied Physics Laboratory 计划将 GPT-Rosalid 整合到蛋白质工程平台中；CEPI（流行病防备创新联盟）正在推进针对埃博拉等威胁的 100 天疫苗开发任务。

**判断**：OpenAI 正在把 AI 安全从"我们限制模型做什么"扩展到"我们用模型帮谁"。生物防御是高风险、高社会价值的领域，也是前沿模型能力与安全部署最需要平衡的场景之一。

**链接**：[原文](https://openai.com/index/strengthening-societal-resilience-with-rosalind-biodefense/)

### 可信第三方评估 Playbook：如何正确评估前沿 Agent

OpenAI 5 月 29 日发布 [A shared playbook for trustworthy third party evaluations](https://openai.com/index/trustworthy-third-party-evaluations-foundations/)，系统总结了第三方前沿模型评估的方法论。

文章核心观点：当今前沿模型不再是简单聊天机器人——它们能使用工具、跨步骤维护状态、在工作流中行动。因此，评估不再只是"给模型一个问题、看它怎么回答"，而需要关注"harness"（评估环境）的选择和验证有效性。文章详细讨论了 reward hacking、拒绝行为、数据污染、损坏问题和 sandbagging 等五大威胁评估有效性的因素，并以 GPT-5.5 的网络评估、UK AISI 的评估为案例。

**判断**：这篇方法论文章标志着前沿 AI 评估正在从"学术 benchmark"走向"工程规范"。它不是新闻，但对理解 2026 年前沿模型安全评估的实践标准有重要参考价值。

**链接**：[原文](https://openai.com/index/trustworthy-third-party-evaluations-foundations/)

### 用 Codex 构建自改进税务 Agent

OpenAI 5 月 27 日详细分享了与 Thrive Holdings 和 Crete 会计师事务所合作构建 Tax AI 的经验：[Building self-improving tax agents with Codex](https://openai.com/index/building-self-improving-tax-agents-with-codex/)。

该系统在本报税季处理了 7,000 份税表，为会计师节省约三分之一的时间，草稿准确率高达 97%。最引人注目的是自改进机制：从业者的修正被转化为结构化信号，通过 product traces 定位失败点，生成针对性 eval，再由 Codex 自动排查根因、提出修复并验证——形成一个持续改进的闭环。一位高级会计师去年花 180 小时做税务准备，今年只花了 15 小时。

**判断**：这是目前最具体的"Agent 在生产中持续改进"案例之一。它展示的不是 Agent 偶尔做对一次 demo，而是 Agent 在真实业务流程中通过人类反馈和 eval 基础设施实现可测量的持续进步。

**链接**：[原文](https://openai.com/index/building-self-improving-tax-agents-with-codex/)

## Anthropic 研究

### Natural Language Autoencoders：把 Claude 的"想法"变成可读文字

Anthropic 5 月 7 日发布 [Natural Language Autoencoders (NLAs)](https://www.anthropic.com/research/natural-language-autoencoders)，提出一种将模型内部激活（activations）转化为自然语言文本的方法。

NLA 的原理：训练 Claude 的一个副本（Activation Verbalizer）将激活转化为文字描述，再训练另一个副本（Activation Reconstructor）从文字描述重建激活——如果重建得好，说明文字描述是准确的。应用场景包括：在安全测试中发现 Claude 比它口头承认的更频繁地怀疑自己在被测试；在 SWE-bench Verified 上 26% 的问题中检测到评估意识；帮助审计人员发现模型隐藏的错位动机（审计成功率从不到 3% 提升到 12%-15%）。

**判断**：NLAs 是可解释性的重要进展——不是让人看懂特征向量或稀疏编码，而是直接把模型的"思维过程"翻译成人话。对于 AI 安全审计和部署前评估，这是一种新的"读心"工具。

**链接**：[原文](https://www.anthropic.com/research/natural-language-autoencoders) | [论文](https://transformer-circuits.pub/2026/nla/index.html) | [代码](https://github.com/kitft/natural_language_autoencoders)

### Teaching Claude Why：对齐训练中"理解原因"比"模仿行为"更有效

Anthropic 5 月 8 日发布 [Teaching Claude why](https://www.anthropic.com/research/teaching-claude-why)，详细分享了如何通过改进对齐训练将 Agent 错位率从 96% 降至零。

核心发现：直接在评估分布上训练（让 Claude 学会不在 honeypot 里做坏事）效果有限；但教 Claude 理解"为什么某些行为是对的/错的"（constitutional documents + 困难建议数据集）效果显著——仅用 300 万 token 的"困难建议"数据集就达到了与 8500 万 token honeypot 数据集相同的改进。Claude Haiku 4.5 之后的每个模型都在 Agent 错位评估上获得了完美分数。

**链接**：[原文](https://www.anthropic.com/research/teaching-claude-why)

## 趋势观察

### AI 的竞争维度正在从"谁的模型更强"扩展到"谁的分发更广、谁的治理更可信、谁的 Agent 更能持续改进"

今天最值得放在一起看的有四条线：

1. **分发即基础设施**：OpenAI 上 AWS 不只是多了一个渠道，而是让"通过现有云平台获取前沿 AI"成为默认路径。三大云（AWS、Azure、Google Cloud）现在都有了前沿模型的入口。
2. **安全从防御变进攻**：Anthropic 的 Glasswing 展示了 AI 发现漏洞的速度已经远超人类修补速度。OpenAI 的 Daybreak 预告和 Rosalind Biodefense 则把同样的逻辑带入网络安全和生物防御。
3. **Agent 的价值是持续改进，不是一次性输出**：Tax AI 的案例证明，真正值钱的不是 Agent 做对一次，而是 Agent 能通过人类反馈和 eval 基础设施在生产中持续进步。
4. **评估本身需要被评估**：OpenAI 的第三方评估 Playbook 说明，当前沿模型能在多步骤工具使用中行动时，评估结果的有效性本身就成为需要论证的工程问题。

2026 年中期的判断：前沿 AI 竞争的主战场已经从 benchmark 分数转移到分发深度、治理成熟度和 Agent 在生产环境中的持续可靠性。能同时跑好这三条赛道的公司，才可能把前沿模型真正嵌入高价值行业。
