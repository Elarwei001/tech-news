# AI 行业日报 - 2026-07-23

> **编者按**：今天的主线不是模型又多会说话，而是 AI 公司正在把 agent、科学基础设施、经济政策研究和底层算力工程一起推进到生产系统里。

## 头条深度

### OpenAI Presence 发布：企业 agent 从 demo 进入生产治理阶段

**事件**：OpenAI 7 月 22 日发布 OpenAI Presence，称其为面向企业的生产级 AI agent 产品，已支持语音和聊天场景。Presence 将模型推理、企业知识、权限策略、护栏、模拟评估、升级规则和 Codex 驱动的上线后改进流程组合在一起，用于客服、外呼销售、内部 IT、保险理赔、银行服务等高价值工作流。OpenAI 称，Presence 已用于自己的英文电话支持渠道，可在无人介入情况下解决 75% 的来电问题，并在 10 天内将人工转接减少 15 个百分点。

**链接**：[原文](https://openai.com/index/introducing-openai-presence/) | [中文译读](../translations/2026-07-23/openai-presence.md) *(AI 译读)*

**为什么重要**：Presence 的价值不在于“又一个客服机器人”，而在于 OpenAI 明确把 agent 产品化的重心放到了 production lifecycle 上：最小权限、政策约束、仿真测试、质量评分、人工接管、生产反馈和受控发布。企业真正需要的不是一次聪明回答，而是能接入业务系统、承担行动、可审计、可回滚、可持续改进的执行层。

**Alex 的分析**：过去一年，AI agent 的叙事经常围绕模型能力本身：长上下文、更强推理、更多工具调用、更高 benchmark。但 Presence 说明，真正把 agent 推进企业系统时，难点会从“模型会不会做”转移到“组织能不能放心让它做”。

这意味着 agent 产品的竞争单位正在变化。模型能力仍然是底座，但企业采购时会更关心一组周边系统：知识如何接入、工具权限如何限制、哪些动作需要审批、错误如何被发现、什么情况升级给人、上线后如何根据真实会话修正政策。Presence 把这些问题打包成产品，也把 Codex 放进持续改进循环：生产日志暴露问题，Codex 建议更新，团队测试后再批准 rollout。

OpenAI 同一天还发布了两条互相呼应的消息：一条是面向美国能源部 Genesis Mission 的国家科学承诺，另一条是 Effingham County 的 3.2GW 数据中心 Project Camellia。合起来看，OpenAI 的路线非常清楚：上层要把 agent 变成企业业务执行系统，中层要把 frontier models 接进国家实验室和科学工作流，底层要继续扩张电力和数据中心。这不是单点产品发布，而是“能力、应用、治理、算力”同时向生产化推进。

## OpenAI

### 推出 OpenAI Presence，面向企业部署可信 agent

**事件**：Presence 支持语音和聊天 agent，面向客户支持、外呼销售和高风险内部工作流。每个部署从明确岗位开始，agent 只获得完成任务所需的知识和系统访问权限；企业定义允许动作、审批要求和人工接管规则。上线前通过模拟和评分检查结果、政策遵守、工具使用与升级行为；上线后通过生产会话和质量信号发现缺口，并由 Codex 建议改进。

**链接**：[原文](https://openai.com/index/introducing-openai-presence/)

**分析**：Presence 是 OpenAI 从 API/ChatGPT 向 forward-deployed enterprise product 扩张的一个明确信号。它把 agent 的核心问题从“模型是否聪明”改写为“企业如何治理一个会采取行动的软件员工”。BBVA、SoftBank、IAG 的设计合作也说明，金融、通信、保险这些高信任场景会成为 production agent 的早期试验场。

### 承诺支持美国能源部 Genesis Mission，把 frontier AI 接入国家科学

**事件**：OpenAI 发布“Advancing the next era of national science”，宣布将支持美国能源部 Genesis Mission。承诺包括向约 2,000 名国家实验室和大学 Genesis 研究人员提供 400 万美元 Codex access，向两个大型科学攻关项目提供 300 万美元 API support，向符合条件的生物项目提供 GPT-Rosalind 能力，向国家实验室领导者提供部分模型和功能的早期可信访问，并向防御型网络安全研究人员扩展 advanced cyber capabilities 的可信访问。

**链接**：[原文](https://openai.com/index/advancing-the-next-era-of-national-science/)

**分析**：这条新闻把 OpenAI for Science 从品牌叙事推进到资源承诺。两个拟定科学 campaign 也很有代表性：高温超导代表 AI + 仿真 + 实验闭环；“machine-accessible frontier atlas”代表用 AI 识别哪些科学问题已经可由现有知识、数据和计算推动。科学 AI 的关键不只是模型答案，而是实验设施、HPC、数据、专家流程和验证标准。

### Project Camellia：OpenAI 在 Georgia 规划 3.2GW 数据中心

**事件**：OpenAI 介绍 Effingham County, Georgia 的 Project Camellia。该项目计划与 Georgia Power Company 签约 3.2GW 电力，分阶段于 2028 至 2032 年交付。OpenAI 称项目采用闭环水系统，承诺不会让居民因该项目承担电力成本，并将在项目周期内提供 8,000 万美元社区收益；此外还将向 Georgia 高校、社区学院和技术学校符合条件的学生提供最高 7,100 万美元 Codex credits。

**链接**：[原文](https://openai.com/index/building-ai-infrastructure-with-the-effingham-county-community/)

**分析**：AI 基础设施竞争正在从“买多少 GPU”进入“能否拿到电、土地、社区许可和长期运营信任”。3.2GW 是一个非常重的信号，说明 frontier AI 的生产化不会只发生在软件层。OpenAI 在文中主动谈居民电价、水使用、社区收益和公开审计，反映数据中心项目的社会许可会成为 AI 扩张速度的一部分。

## Anthropic

### 发布 Economic Futures Research Fund 研究议程

**事件**：Anthropic 7 月 22 日公布 Economic Futures Research Fund 的研究议程，称将投入 2 亿美元支持外部研究，目标是评估哪些干预措施能帮助社会应对 AI 带来的经济影响。基金优先五个方向：AI 对企业和工作场所层面的影响、帮助人们应对 AI 驱动的职业转型、现代化收入支持、在冲击到来前建立劳动者分享 AI 增长的机制，以及为公共投资生成新证据。Anthropic 表示，项目通常在 500 万至 3,000 万美元区间，不直接资助低于 100 万美元的申请。

**链接**：[原文](https://www.anthropic.com/news/economic-futures-research-fund-agenda)

**分析**：这不是模型新闻，但很重要。Anthropic 正把“AI 将改变劳动力市场”从观点变成实证研究 agenda。值得注意的是，它更偏好大规模 RCT、试点和项目评估，而不是只资助论文。这与 AI 扩散速度有关：如果政策证据等传统发表周期结束才出现，可能已经太晚。

### Claude 可直接查询 Anthropic Economic Index

**事件**：Anthropic 同日介绍 Anthropic Economic Index connector，允许用户通过 Claude 探索 Economic Index 中关于 AI 如何被使用的真实数据。Anthropic 称，该 Index 的数据已被研究者、记者和政策制定者使用，connector 让更广泛用户可以提出自然语言问题并分析趋势。

**链接**：[原文](https://www.anthropic.com/news/anthropic-economic-index-connector)

**分析**：这条产品更新和基金议程是组合拳：一边资助外部研究，一边把自有使用数据变成可查询公共资源。AI 公司在经济影响议题上的角色正在变复杂：它们既是被研究对象，也是数据提供者、研究资助者和政策参与者。

## Google Research

### SymptomAI：用真实人群研究评估日常症状问诊 agent

**事件**：Google Research 7 月 22 日发布 SymptomAI 研究，称这是一个面向日常症状评估和差异诊断的对话式 AI agent 研究。研究通过 Fitbit app 招募 13,917 名同意参与者，并将其随机分配到五种不同问诊策略。研究团队对其中部分参与者的医疗服务提供者诊断与临床专家标注进行评估，发现 SymptomAI 的 differential diagnosis 更常被临床评审认为准确；所有主动追问信息的 agent 策略均显著优于用户主导的 baseline。

**链接**：[原文](https://research.google/blog/symptomai-towards-a-conversational-ai-agent-for-everyday-symptom-assessment/)

**分析**：SymptomAI 的价值在于它避开了只用完美病例 vignette 测医疗 AI 的老问题，转向真实人群、真实表达、真实不完整症状描述。它也提醒我们，医疗 agent 的核心不只是给出诊断，而是能否通过高质量追问补齐上下文。风险同样清楚：这些结果仍是研究分析，不等同于临床诊断，部署前还需要安全监督、监管和责任边界。

### 用强化学习让量子计算机在运行中自我校准

**事件**：Google Quantum AI 和 Google Research 发布“Towards a quantum computer that learns from its errors”，介绍发表于 Nature 的“Reinforcement learning control of quantum error correction”。研究展示了一个强化学习框架，让自主 agent 从量子错误检测中学习，持续调整数千个控制参数，使量子系统在计算过程中抵抗硬件漂移并保持稳定。

**链接**：[原文](https://research.google/blog/towards-a-quantum-computer-that-learns-from-its-errors/)

**分析**：这条研究和主流生成式 AI 看似距离较远，但它体现了一个重要趋势：AI 正在进入复杂科学设备的控制回路。量子计算的瓶颈之一是校准与计算相互中断；如果系统能在“音乐继续播放时调音”，长期量子计算才更接近工程现实。

## NVIDIA

### TensorRT engine build 变得可观察、可取消

**事件**：NVIDIA Developer Blog 7 月 22 日发布教程，介绍如何用 TensorRT 的 `IProgressMonitor` API 让长时间 engine build 在 Python 或 C++ 中可观察、可取消。文章指出，大模型、深度 tactic search 和冷 timing cache 可能让构建持续数秒到数分钟；对 agent runtime、IDE、HTTP service 或 CI 来说，缺少进度与取消路径会浪费 GPU-hours 并造成卡住的会话。

**链接**：[原文](https://developer.nvidia.com/blog/make-long-running-nvidia-tensorrt-engine-builds-observable-and-cancelable-in-python-or-c/)

**分析**：这是一篇工具教程，但对 agent 系统很实际。agent 不只需要调用模型，也会触发编译、构建、部署、推理优化等长任务。可观察和可取消不是 UI 细节，而是 production agent 的资源治理能力。

### Rubin GPU 与 Vera CPU 继续补齐 agentic AI factory 栈

**事件**：NVIDIA 7 月 21 日连续发布 Rubin GPU 和 Vera CPU 技术文章。Rubin GPU 面向长上下文、多步推理、MoE decode 和低延迟交互，强调 3360 亿晶体管、288GB HBM4、22TB/s 峰值带宽、NVLink 6 与 confidential computing；Vera CPU 的 Olympus core 则面向 agent runtime、解释器、编译器、图分析和工具调用等 branch-heavy、latency-sensitive 路径，强调单线程性能、coherent fabric、SOCAMM2 LPDDR5X 和 CXL 3.1。

**链接**：[Rubin GPU 原文](https://developer.nvidia.com/blog/inside-nvidia-rubin-gpu-architecture-powering-the-era-of-agentic-ai/) | [Vera CPU 原文](https://developer.nvidia.com/blog/inside-nvidia-vera-cpu-olympus-cores-built-for-maximum-single-threaded-performance-in-agentic-ai)

**分析**：NVIDIA 的表述越来越明确：agentic AI factory 不是 GPU alone。agent 工作负载会在 GPU、CPU、网络、内存、安全隔离、存储和软件 runtime 之间来回移动。Rubin 解决大规模推理的吞吐和能效，Vera 解决 CPU 侧不规则控制流和工具链执行，TensorRT 进度监控则解决构建任务的运行治理。这些都指向同一件事：agent 时代的基础设施是端到端系统。

## 趋势观察

### AI 公司正在同时争夺四层生产化能力

今天的一手信息源合起来看，AI 行业正在同时争夺四层能力。

第一层是应用生产化。OpenAI Presence 把 agent 放进客服、银行、保险、IT 等具体流程，强调权限、评估、升级和上线后改进。

第二层是科学生产化。OpenAI 支持 Genesis Mission，Google Research 发布 SymptomAI 和量子控制研究，Meta 近期展示开放视觉模型进入国家实验室影像管线。AI 不再只是辅助写作，而是在进入科学工作流和实验设备控制回路。

第三层是社会治理生产化。Anthropic 的 2 亿美元 Economic Futures Research Fund 说明，AI 经济影响已经进入政策实验与证据生产阶段。

第四层是基础设施生产化。OpenAI 的 3.2GW Georgia 数据中心、NVIDIA 的 Rubin/Vera/TensorRT 工具链共同说明，agent 和 frontier models 的能力最终要落到电力、冷却、CPU、GPU、网络、编译与可运维性上。

这也是 2026 年 AI 新闻越来越“重”的原因：行业已经越过单纯模型发布周期，进入真实系统建设周期。谁能把能力、产品、治理和基础设施连起来，谁才更可能把 AI 从演示带到长期生产。
