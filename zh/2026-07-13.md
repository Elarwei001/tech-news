## 头条深度

### AlphaEvolve GA：Google Cloud 把算法发现 agent 交给企业客户

**事件**：Google Cloud 7 月 9 日宣布 AlphaEvolve 在 Gemini Enterprise Agent Platform 上正式 GA。AlphaEvolve 是一个基于 Gemini 的代码优化与算法发现 agent，用户给出基准程序、问题定义和评分函数，它会在候选程序空间中自动生成、测试、评分和迭代，目标是找到可直接进入生产环境的优化实现。Google 称该系统已在物流、半导体、基因组学、高性能计算、金融服务、广告和科学计算等领域试用。

**链接**：[原文](https://cloud.google.com/blog/products/ai-machine-learning/alphaevolve-is-available-for-everyone) | [中文译读](../translations/2026-07-13/google-alphaevolve-ga.md) *(AI 译读)*

**为什么重要**：AlphaEvolve 和普通 coding agent 的差别在于，它不是只帮工程师完成一个明确任务，而是把“搜索空间”本身产品化。开发者不只是让模型改一段代码，而是定义一个可验证的优化目标，然后让 agent 在大量候选实现中寻找更优解。这更接近自动化研发系统，而不是聊天式代码助手。

**Alex 的分析**：过去一年，agent 产品的主线大多围绕“执行工作”：打开工具、读取上下文、调用 API、生成文档或代码。AlphaEvolve 把问题往前推了一步：如果目标函数足够清楚，agent 不只是执行已知步骤，还可以探索未知实现。

这件事对企业 AI 很关键。企业里最有价值的优化问题，往往不是“写一个新函数”，而是“让已有系统在约束下变快、变准、变省”。供应链路径、仓库调度、芯片设计、GPU kernel、金融预测、营销模型、科学模拟，全都属于这种类型。人类工程师知道如何评估答案，但很难穷举候选方案；AlphaEvolve 试图把这个穷举过程交给模型和自动评分系统。

Google 给出的客户案例显示，它正在把 AlphaEvolve 定位成跨行业的“可执行搜索引擎”。Coolblue 用它优化 28 天需求预测；FM Logistic 在仓库路径上取得 10.4% 改进；Kinaxis 报告预测指标提升并显著降低运行时间；Klarna 用它重写大型 ML 训练管线，提升吞吐；ORNL 把它接到 Frontier 超算上搜索混合精度 GPU kernel；PacBio 用它降低变异检测错误；WPP 用它优化广告效果预测模型。

这些案例都指向同一个变化：AI agent 的价值开始从“会不会写代码”转向“能不能闭环验证”。AlphaEvolve 的四步流程是 Define、Measure、Optimize、Apply，其中 Measure 是核心。没有确定的评分函数，agent 只能给出看似合理的建议；有了可执行 evaluator，系统就能让每次候选变更接受同一把尺子的检验。

这也解释了为什么 Google 同期反复强调 agent evaluation、ADK 工作流、AutoRaters 和 Gemini Enterprise Agent Platform。企业不会把生产系统交给一个只会自信输出的模型；它们需要可复现的评估、可审计的实验、可回滚的产物，以及明确的人类批准点。AlphaEvolve 是 Google 把这些基础设施组合成一个商业产品的代表案例。

真正值得关注的是边界。AlphaEvolve 适合有明确评估函数的问题；对目标含糊、用户偏好强、反馈延迟长的任务，它的优势会下降。它也不会取消工程师角色，反而要求工程师更擅长定义 baseline、约束、指标和上线标准。未来的高级工程工作，可能会越来越像设计实验环境：人定义问题和评价体系，agent 在里面跑大规模搜索。

所以今天的头条不只是“Google 又发布一个 agent”。它说明 AI 产品竞争正在进入更硬的阶段：不是谁能生成更多文本或代码，而是谁能把模型接入真实评估回路，持续发现更好的可运行方案。

## Google

### Cloud：AlphaEvolve 在 Google Cloud 正式 GA

**事件**：AlphaEvolve 现已通过 Gemini Enterprise Agent Platform 对客户开放。Google 描述的部署流程包括：定义基准算法和问题背景；建立评分函数；由 agentic harness 生成并优化候选代码；将通过验证的结果应用到生产工作负载。Google 同时给出多个行业案例，包括 BASF、Coolblue、FM Logistic、Infineon、JetBrains、Kinaxis、Klarna、ORNL、PacBio、qBraid、Schrodinger、WPP 等。

**链接**：[原文](https://cloud.google.com/blog/products/ai-machine-learning/alphaevolve-is-available-for-everyone)

**分析**：Google 的路线很明确：把 Gemini 从模型入口变成企业优化基础设施。AlphaEvolve 不是通用聊天产品，而是面向“可评分代码搜索”的工具。它要求企业先把问题工程化，再让模型在受控边界内探索。这和消费级 agent 的“多做事”不同，更像企业软件中的自动化研发模块。

### Developers：LiteRT.js 将 Google 的边缘 AI runtime 扩到 Web

**事件**：Google Developers 7 月 9 日发布 LiteRT.js，面向 JavaScript 开发者在浏览器中运行机器学习模型，支持 WebGPU、未来的 WebNN，以及 WebAssembly CPU fallback。该项目把 LiteRT 的跨平台边缘 AI runtime 扩展到 Web 端。

**链接**：[原文](https://developers.googleblog.com/litertjs-googles-high-performance-web-ai-inference/)

**分析**：LiteRT.js 和 AlphaEvolve 是同一张图的两侧。前者让模型推理更靠近用户设备和浏览器，后者让模型进入企业算法优化流程。Google 的优势不只在模型，而在把 AI 分发到 Cloud、Web、Edge、Android 和 Workspace 等多个运行环境。

## NVIDIA

### Robotics：RoboLab 试图让通用机器人策略评测摆脱静态 benchmark

**事件**：NVIDIA Technical Blog 7 月 11 日发布机器人策略评测文章，介绍 RoboLab，用于评估通用机器人策略在真实部署前的能力。文章指出现有机器人 benchmark 存在视觉域重叠、任务集固定导致饱和、失败诊断不足、统计置信度不够等问题。RoboLab 通过自动生成多样化场景、任务标签、分级评分、轨迹质量和失败事件日志来提高评测信息量，并计划从 2026 年 8 月起集成到 NVIDIA Isaac Lab-Arena。

**链接**：[原文](https://developer.nvidia.com/blog/how-to-evaluate-general-purpose-robot-policies-for-real-world-deployment/)

**分析**：机器人领域正在遇到和 coding agent 类似的问题：模型越来越强，旧 benchmark 越来越容易被刷满。NVIDIA 的重点不是再展示一个机器人 demo，而是建设能区分真实泛化能力的评测基础设施。对具身 AI 来说，评测质量会直接影响模型、仿真平台和真实部署的速度。

## 趋势观察

### Agent 竞争进入“评估闭环”阶段

今天最值得看的不是某个模型参数，而是两个基础设施信号：Google AlphaEvolve 和 NVIDIA RoboLab。

AlphaEvolve 说明，企业 agent 的高价值场景会越来越依赖自动化评估。只要问题能被评分，agent 就能从“建议者”变成“搜索者”，持续生成、测试、淘汰和改进候选方案。RoboLab 则说明，在机器人和具身 AI 中，评测本身已经成为瓶颈：如果 benchmark 静态、样本不足、失败不可诊断，再强的模型也很难被可靠比较。

这两条线共同指向 2026 年下半年的一个关键词：闭环。模型生成只是第一步，真正的价值来自生成之后能否被运行、评分、诊断、追踪和应用。谁掌握更强的评估闭环，谁就更接近把 agent 带进生产系统。
