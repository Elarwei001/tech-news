# AI 行业日报 — 2026-06-26

> **编者按**：今天最值得关注的不是某个新模型，而是 agent 正在从“会聊天的工具”变成企业里的可委派劳动单位；OpenAI 用 Codex 使用数据给出量化证据，Mistral 和 NVIDIA 则分别补上连接器治理、专用工具和生产基础设施。

## 头条深度

### OpenAI 量化 Codex 使用：agent 正在把知识工作的单位从对话改成任务

**事件**：OpenAI 6 月 25 日发布经济研究文章《How agents are transforming work》，用 Codex 在个人用户、组织用户和 OpenAI 内部的使用数据，衡量 agentic AI 如何进入真实工作流。OpenAI 称，到 2026 年 5 月，抽样个人用户中 80.6% 至少发起过一次估计超过 30 分钟人工工作量的 Codex 请求，70.2% 发起过超过 1 小时的请求，25.6% 发起过超过 8 小时的请求。OpenAI 内部也出现明显迁移：Codex 已成为所有部门的主要 AI 工作工具，平均员工 85% 以上的输出 token 来自 Codex，而每周总输出 token 中 Codex 占比达到 99.8%。

**链接**：[原文](https://openai.com/index/how-agents-are-transforming-work/) | [中文译读](../translations/2026-06-26/openai-agents-transforming-work.md) *(AI 译读)*

**为什么重要**：这篇文章的价值不在于证明 Codex “增长很快”，而在于它给出了一个更清晰的工作单位变化：chatbot 的基本单位是一次交互，agent 的基本单位是一个被委派、可运行、可验证、可并行的任务。

这个变化会重塑企业采用 AI 的方式。过去的采用问题是“员工会不会用 AI 帮自己写邮件、总结资料、生成代码片段”；现在的问题变成“组织能不能把跨系统、长时间、带权限的工作交给 agent，同时保留审计、成本、身份和失败恢复机制”。这也是为什么今天其他几条新闻都围绕同一件事展开：Mistral 加强 connectors 的权限和调试，NVIDIA 推 Agent Toolkit 和 BioNeMo Agent Toolkit，AWS 与 NVIDIA 把向量检索和 GPU 实例做成更可生产化的基础设施。

**Alex 的分析**：OpenAI 的数据把一个常被模糊讨论的现象说具体了：agent 的采用并不是只发生在工程师群体。OpenAI 称，自 2025 年 8 月以来，非开发者个人用户增长 137 倍，组织用户中的非开发者增长 189 倍；公司内部 Legal、Finance、Recruiting 等非技术部门在 2026 年 4 月左右也转向以 Codex 为主。更有意思的是任务边界的迁移：OpenAI 观察到商业职能员工通过 Codex 完成的工作中，超过四分之一属于工程或编码。

这不是说每个人都要变成程序员，而是说 agent 降低了跨职能执行的摩擦。一个运营、财务或法务人员不一定需要亲手写生产代码，但可以让 agent 做数据转换、自动化、排查、结构化分析和内部工具原型。真正稀缺的能力因此从“会不会操作某个软件”转向“能不能提出正确任务、设定边界、判断输出、承担责任”。

当然，这些数据也需要谨慎理解。OpenAI 明确说明，任务时长是用 LLM-as-judge 基于 Codex transcript 估计的，阈值应被视为方向性而非精确测量；内部 OpenAI 用户也不是普通企业的代表样本。但即便如此，趋势已经足够清楚：agent 产品的竞争会从单次回答质量，进入长程执行、并行调度、权限控制、成本可视化和组织流程重构。

## OpenAI

### Economic Research：Codex 从工程工具扩散到全公司工作层

**事件**：OpenAI 文章称，Codex 使用随着能力增强和产品功能扩展而增长。到 2026 年 6 月，OpenAI 内部 99 分位用户每天会生成超过 60 小时的 Codex agent turns，分布在多个并行 agent 上。研究、客服和工程等部门的 Codex 输出 token 中位数相较 2025 年 11 月分别增长 56 倍、32 倍和 27 倍，Legal 增长 13 倍。

**链接**：[原文](https://openai.com/index/how-agents-are-transforming-work/)

**分析**：这说明 agent 产品的核心指标不再只是活跃用户，而是“可委派工作量”。如果用户一天能并行启动多个小时级任务，产品设计就必须处理队列、状态、权限、回滚、失败解释和结果验收。

### Developers：DevDay 2026 定档 9 月 29 日

**事件**：OpenAI 发布 DevDay 2026 页面，宣布年度开发者大会将于 9 月 29 日在旧金山举行，目前开放通知订阅。

**链接**：[原文](https://openai.com/index/devday-2026/)

**分析**：结合本周 Jalapeno、Daybreak、Codex 研究和 DevDay 预告，OpenAI 很可能会把 2026 年下半年的开发者叙事集中在 agent、基础设施和安全治理三条线。

## Mistral AI

### Engineering：Connectors 增加组织级治理和调试能力

**事件**：Mistral 6 月 24 日发布 connectors 更新，新增 workspace/org 级访问控制、connector 内单个 tool 开关、带 connector scope 的 API keys、多账号 connectors、Connectors Debugger、Vibe Code connectors，以及 Workflows 中的 connectors public preview。Mistral 称 connector 目录目前覆盖 60 多个集成。

**链接**：[原文](https://mistral.ai/news/more-control-over-connectors/)

**分析**：这是 agent 进入企业生产环境时最现实的一层。演示里接上 CRM、邮箱和知识库很容易；生产中难的是身份、最小权限、服务账号、token 过期、失败定位和不同团队的访问边界。Mistral 把 connectors 做成治理对象，方向是对的。

### Research：OCR 4 把文档理解变成 agent 可用的结构化输入

**事件**：Mistral OCR 4 支持 170 种语言、bounding boxes、block classification、inline confidence scores、自托管部署，并可作为 enterprise search、RAG 和 domain-specific retrieval pipeline 的 ingestion 组件。Mistral 标价为 API 每 1,000 页 4 美元，Batch API 每 1,000 页 2 美元，Document AI 每 1,000 页 5 美元。

**链接**：[原文](https://mistral.ai/news/ocr-4/)

**分析**：如果 agent 要处理真实企业流程，文档不是“附件”，而是主要工作对象。OCR 4 的重点不是只抽文本，而是把页面位置、区块类型和置信度变成下游检索、引用、人工复核和表单处理可以使用的结构。

## NVIDIA

### AI Infrastructure：NVIDIA 与 AWS 强化生产级 AI 基础设施

**事件**：NVIDIA 6 月 23 日介绍与 AWS 的合作：Amazon EC2 G7 instances 使用 NVIDIA RTX PRO 4500 Blackwell Server Edition GPU，面向 AI inference、graphics、spatial computing 和 GPU-accelerated data analytics；Amazon OpenSearch Serverless 将由 NVIDIA cuVS 驱动的 GPU-accelerated vector indexing 作为 vector collections 的默认计算选择。NVIDIA 称 G7 相比 G6 可提供最高 4.6 倍 AI inference 性能，OpenSearch vector indexing 可比 CPU-only 构建快最高 10 倍、成本约为四分之一。

**链接**：[原文](https://blogs.nvidia.com/blog/nvidia-aws-ai-production-scale/)

**分析**：agent 的体验最终会卡在检索、低延迟推理和弹性基础设施上。NVIDIA/AWS 这类合作把“可生产化”做进云基础设施，而不是让每个企业自己拼 GPU、向量库和扩缩容。

### Agent Toolkit：NVIDIA 用模型、工具、skills 和 runtime 组合企业 agent 底座

**事件**：NVIDIA 6 月 23 日介绍 Agent Toolkit，定位为由 models、tools、skills 和 secure runtime 组成的开放模块化基础。它包含 Nemotron open models、NemoClaw blueprints 和 OpenShell runtime，并支持第三方 agent harness 与 orchestration frameworks。

**链接**：[原文](https://blogs.nvidia.com/blog/nvidia-agent-toolkit-open-models-tools-skills-secure-runtime-ai-agents/)

**分析**：NVIDIA 的叙事正在从“提供 GPU”扩展到“提供企业 agent 的运行层”。如果 OpenAI 的文章强调 agent 使用增长，NVIDIA 这里强调的是让 agent 在行业工作流中安全运行、调用工具、接入数据和被企业控制。

### Life Sciences：BioNeMo Agent Toolkit 面向科学发现

**事件**：NVIDIA 发布 BioNeMo Agent Toolkit，面向 biology、chemistry、genomics 和 drug discovery。NVIDIA 称该工具包把 BioNeMo、NIM microservices、Parabricks、NeMo、Nemotron 等能力包装为 agent 可调用的科学工具，并已有 50 多家公司使用；Anthropic 和 OpenAI 也在进行集成。

**链接**：[原文](https://nvidianews.nvidia.com/news/nvidia-launches-bionemo-agent-toolkit-giving-ai-agents-the-tools-to-accelerate-scientific-discovery)

**分析**：这条新闻说明 agent 的高价值场景会很快走向行业专用化。科学 agent 不只是读论文摘要，而是要调用蛋白结构预测、分子 docking、genomic analysis、biomarker discovery 等工具，形成可复现的实验与推理循环。

## Google DeepMind / Google AI

### Agent Safety：computer use 与 AI Control Roadmap 成为背景变量

**事件**：Google 本周把 computer use 内置进 Gemini 3.5 Flash，并通过 AI Control Roadmap 强调把内部 agent 当作潜在 insider threat 管理，使用 supervisor、检测、阻断、覆盖率、召回率和响应时间等指标评估安全。

**链接**：[Gemini computer use](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-computer-use-gemini-3-5-flash/)；[AI Control Roadmap](https://deepmind.google/blog/securing-the-future-of-ai-agents/)

**分析**：今天 OpenAI、Mistral 和 NVIDIA 的新闻都在说同一件事：agent 要进入真实工作，就必须有控制面。Google 的安全路线图提醒行业，控制面不仅是产品权限设置，也是系统级监督与响应能力。

## 趋势观察

### 2026 年的关键词不是“更聪明”，而是“可委派”

今天的新闻共同指向一个判断：前沿 AI 产品正在从回答问题，转向承担任务。

OpenAI 给出 Codex 使用数据，说明长程、并行、跨职能 agent work 已经在前沿用户中出现；Mistral 把 connectors 的权限、身份和调试做成产品能力；NVIDIA 把 agent 所需的模型、工具、runtime、检索和云基础设施组合成生产栈；Anthropic 与 Google 则分别从协作入口和安全控制面补足组织采用条件。

这会改变企业购买 AI 的问题清单。过去问“模型准确吗、会不会幻觉、价格多少”；未来会问“能委派多久、能用哪些工具、失败怎么恢复、谁承担权限、审计在哪里、每个任务成本能否预测、结果如何验收”。模型能力仍然重要，但真正的产品竞争会发生在模型之外。
