## 头条深度

### OpenAI Tax AI：自我改进 agent 的关键不是自动化，而是可验证的反馈闭环

**事件**：OpenAI 5 月 27 日发布工程文章 [Building self-improving tax agents with Codex](https://openai.com/index/building-self-improving-tax-agents-with-codex/)，介绍 OpenAI 与 Thrive Holdings 团队如何为 Crete 会计师网络共同开发 Tax AI。该系统在本报税季试点处理了 7,000 份 1040 和 1041 报税表，通过专家反馈、生产 traces 和 Codex 驱动的 eval 循环持续改进。

**为什么它值得做头条**：这不是“AI 写税表”的普通自动化故事，而是 agent 工程范式的一个清晰样板。OpenAI 给出的核心答案是：生产环境中的失败不能只靠工程师事后排查，也不能直接丢给 agent “自己修”。真正可扩展的做法，是把专家修正沉淀成结构化证据，把重复失败转成 eval，再让 Codex 在限定代码面、明确成功标准和回归测试中提出修复。

**关键信息**：

- Tax AI 面向 Crete 网络中 30 多家会计师事务所，试点期间处理 7,000 份报税表。
- OpenAI 称，Tax AI 可为税务准备工作节省约三分之一时间，草拟报税表最高达到 97% 准确率，并让吞吐量提升约 50%。
- 系统上线时，只有四分之一报税表达到 75% 字段正确完成率；六周内，这一比例提升到 86%。
- 改进闭环由三部分组成：贴近从业者、让产品生产结构化证据、用 Codex 将可操作问题转成 eval 和有边界的工程任务。
- OpenAI 明确保留人类责任边界：工程师负责架构、产品决策和上线，从业者通过修正、复核、批准最终报税表来驱动学习循环。

**深度分析**：

OpenAI 这篇文章重要的地方，不在于税务本身，而在于它把“agent 如何在生产里变好”讲得比多数发布会更具体。

过去很多 agent 演示停在两个层面：要么证明模型能执行复杂任务，要么展示它能调用工具、修改代码、提交结果。但真实业务系统里的难点往往不是“能不能做一次”，而是“出错后能不能把错误变成可重复改进”。报税就是典型场景：源文件凌乱，客户备注、往年资料、表格字段、人工判断混在一起；一个字段被修改，可能是抽取失败，也可能是会计师偏好、税务判断、产品尚不支持的流程，或正常噪音。

这解释了为什么 Tax AI 的核心不是更强 prompt，而是证据链。系统必须保留从原始文件、字段抽取、来源引用、税务引擎映射，到专家修正和最终提交的完整路径。只有这样，生产环境里的“人改了什么”才不会只是一个后验结果，而能变成可审查的 failure signal。

Codex 在这个架构里的角色也值得注意。它不是一个被要求对所有失败负责的黑箱，而是在一个有边界的工程环境里工作：有 repo、任务描述、生产 trace、目标 eval、回归套件和工程复核。重复出现的问题先被人和系统归类为可操作 finding，再变成 Codex 可调查、可修改、可验证的任务。模糊或不安全自动化的案例则回到产品团队，而不是强行进入自动修复流程。

今天的判断：这代表企业 agent 的竞争开始从“模型会不会做任务”转向“组织能不能把生产反馈转成可验证改进”。未来最强的 agent 产品，不一定是最会自由发挥的系统，而是最会把专家动作、生产痕迹、eval、权限边界和工程审查组合成连续学习机器的系统。

## Anthropic

### 社科研究里的 coding agents：采用率不高，但差距已经明显

Anthropic 5 月 27 日发布 [Coding agents in the social sciences](https://www.anthropic.com/research/coding-agents-social-sciences)。文章基于 2026 年 2 月至 3 月对 1,260 名社科研究者的调查：81% 受访者尝试过在研究中使用 AI chatbot，但只有 20% 每周使用命令行集成的 coding agent，如 Claude Code、Codex、Cursor 或 Google Antigravity。

更值得关注的是采用差距。Anthropic 称，经济学和政治学采用率更高，博士生和博士后高于终身教授，通常男性姓名的研究者采用 coding agents 的比例超过通常女性姓名研究者的两倍，顶尖大学研究者也明显更可能使用这些工具。coding agent 用户报告的 working papers 和 grant proposals 更多，但 Anthropic 明确提醒，这只是描述性差异，不能直接解释为因果效果。

**判断**：这篇研究和 OpenAI Tax AI 正好互为镜像。OpenAI 展示 agent 在专业系统中如何变好；Anthropic 则提醒，谁先拥有并学会这些工具，可能会改变知识生产的分布。agent 不是均匀扩散的生产力工具，它会先奖励已有技术资本、组织资源和职业压力更强的人群。

**链接**：[原文](https://www.anthropic.com/research/coding-agents-social-sciences)

## OpenAI

### Codex 从开发工具变成业务改进循环的一部分

OpenAI 今天的 Tax AI 文章把 Codex 放进了一个更具体的企业软件位置：它不只是帮工程师写代码，而是连接生产反馈、领域专家判断、eval 和 pull request 的循环。Tax AI 在租赁房产等复杂报税场景中，把专家修正转成字段级 review rows，再把重复问题归类成 eval targets，最后让 Codex 在受限工程环境中定位根因、修改 schema/mapper/grader 或检索逻辑，并通过目标 eval 和回归套件验证。

**判断**：这比“AI agent 替代白领任务”的叙事更务实。OpenAI 在强调一个企业会更容易接受的版本：agent 做持续改进，但架构、上线、最终专业责任仍由人类掌握。这种边界感会是 agent 进入金融、税务、法务、医疗和企业运营的必要条件。

## 趋势观察

### Agent 的下一阶段是“可运营”，不是“更像人”

今天的两条最有价值的一手更新其实在讲同一件事：agent 正在进入严肃工作流，但真正的瓶颈是运营系统，而不是演示能力。

OpenAI Tax AI 说明，一个 agent 要在税务这种高责任场景里产生价值，需要专家反馈、生产证据、eval、权限边界和工程复核。Anthropic 的社科调查说明，coding agents 进入研究工作后，最先受益的不是所有人，而是更年轻、更技术化、更接近高资源机构的人群。Google 在铺 agent 平台，NVIDIA 在铺 agent 基础设施，Meta 暂时低调。

这意味着 2026 年 agent 竞争会越来越像企业软件竞争：谁能接住真实工作流里的脏数据、模糊责任、长期改进和审计要求，谁就更可能留下来。模型能力仍然重要，但它只是原材料。真正的壁垒会来自把能力组织进可验证、可追踪、可治理的生产系统。

今天的判断：AI 公司正在从“展示 agent 能做什么”进入“证明 agent 能被运营”的阶段。
