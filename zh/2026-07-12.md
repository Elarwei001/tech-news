## 头条深度

### ChatGPT Work：OpenAI 把 Codex、桌面端、定时任务和 Sites 合成一个工作 agent

**事件**：OpenAI 7 月 9 日发布 ChatGPT Work，将其定义为 ChatGPT 内的工作型 agent。它可以跨应用和文件收集上下文，长时间跟进项目，把目标拆成步骤，并生成 sheets、slides、docs、web apps 等完成品。OpenAI 称，Codex 每周有超过 500 万用户，其中超过 100 万人已将其用于软件开发以外的工作；ChatGPT Work 由 GPT-5.6 驱动，并与新的 ChatGPT desktop app、Scheduled Tasks、plugins、Computer Use、Sites in ChatGPT public beta 结合。

**链接**：[原文](https://openai.com/index/chatgpt-for-your-most-ambitious-work/) | [中文译读](../translations/2026-07-12/openai-chatgpt-work.md) *(AI 译读)*

**为什么重要**：这条发布没有昨天 Deutsche Telekom 案例那么“行业化”，但它更直接说明 OpenAI 想把 ChatGPT 变成什么：不是一个聊天框，而是一个能连接工作上下文、调用工具、操作桌面、按计划运行、产出可分享成果的执行层。它把 Codex 的长期任务能力从代码扩展到销售、财务、市场、运营和数据分析。

**Alex 的分析**：ChatGPT Work 的重点不是“AI 帮你写文档”，而是 OpenAI 正在重新定义知识工作的产品边界。

过去的 ChatGPT 更像一个通用入口：用户带着问题进来，模型返回回答。ChatGPT Work 则改变了交互单位。用户给的不是一个问题，而是一个目标；模型交付的不是一段文字，而是一组可检查、可修改、可发布的工作产物。这个变化看似细微，但产品含义很大：AI 从 answer engine 变成 work system。

OpenAI 把几块能力放在同一个入口中。Plugins 负责连接 Slack、Teams、Drive、SharePoint、CRM、邮件和日历。Computer Use 负责操作本地应用和浏览器。Scheduled Tasks 负责把 agent 变成长期运行的自动化。Sites 负责把结果从静态文档推向交互式 web app。Codex 并入 ChatGPT desktop app，则说明 coding agent 不再只是开发者工具，而是通用工作 agent 的底层能力之一。

这也解释了 GPT-5.6 发布中那些看似工程化的功能为什么重要。Programmatic Tool Calling、multi-agent、长任务、模板跟随、computer use、artifact generation，都不是 demo 功能，而是让 ChatGPT Work 能跨系统交付结果的运行时能力。模型能力越强，产品越需要围绕权限、审计、批准和可恢复的工作流重新设计。

真正的风险也在这里。一个能跨应用操作、自动检查新信息、更新文件并分享结果的 agent，必须被企业治理约束。OpenAI 因此强调 Enterprise/Edu 管理员可以控制访问、工具连接、浏览器网络、敏感操作和 spend controls，并用 Compliance API 与 auto-review 提供可见性和预审。

所以 ChatGPT Work 是 GPT-5.6 周期中最值得补看的产品信号：frontier model 的下一步商业化，不只是卖 API token，而是把模型嵌进人们每天工作的应用、文件、浏览器和审批链条中。

## OpenAI

### Product：GPT-5.6 进入 Microsoft 365 Copilot，成为新的 preferred model

**事件**：OpenAI 7 月 9 日宣布，GPT-5.6 将成为 Microsoft 365 Copilot 在 Word、Excel、PowerPoint、Chat 和 Cowork 中的新 preferred model。OpenAI 称，这会帮助用户在常用生产力工具中生成更高质量的文档、分析、演示和跨团队协作成果。Microsoft 也会通过 OpenAI API 直接接入模型，为 Microsoft 365 客户提供 GPT-5.6 能力。

**链接**：[原文](https://openai.com/index/gpt-5-6-preferred-model-microsoft-365-copilot/)

**分析**：这条新闻和 ChatGPT Work 形成正反两面。ChatGPT Work 是 OpenAI 自己打造工作入口；Microsoft 365 Copilot 则是把同一代模型送进既有办公套件。OpenAI 的企业路线正在同时押注两个渠道：自有 agent workspace 和合作伙伴分发。

### Research：OpenAI 审计 SWE-Bench Pro，估计约 30% 任务存在破损

**事件**：OpenAI 7 月 8 日发布 coding evaluations 审计文章。研究团队审查 SWE-Bench Pro 后认为，公开 split 的 731 个任务中存在显著比例的问题：自动分析 pipeline 标记 200 个破损任务，占 27.4%；人工标注 campaign 识别 249 个，占 34.1%。主要问题包括测试过严、提示不充分、测试覆盖低，以及提示与测试要求矛盾。OpenAI 因此估计约 30% 的 SWE-Bench Pro 任务存在破损。

**链接**：[原文](https://openai.com/index/separating-signal-from-noise-coding-evaluations/)

**分析**：这篇文章的价值不只在于质疑某个 benchmark。agentic coding 正进入真实工程任务，评测如果不能区分“模型失败”和“任务本身不公平”，就会误导模型发布、安全判断和研发优先级。更有意思的是，OpenAI 用 agent-assisted audit 来检查评测数据，这说明 agent 也开始进入 AI 评测基础设施本身。

### Voice：GPT-Live 成为 ChatGPT Voice 新一代语音模型

**事件**：OpenAI 7 月 8 日发布 GPT-Live，面向自然人机语音交互。GPT-Live-1 将成为 Go、Plus、Pro 用户的 ChatGPT Voice 默认模型，GPT-Live-1 mini 将成为 Free 用户默认模型。OpenAI 表示模型已在 iOS、Android 和 ChatGPT.com 全球 rollout；发布时不支持 voice with video 或 screen sharing，但这些能力仍在规划中。OpenAI 也强调，GPT-Live 使用预设声音，并有防止模仿真人声音的保护措施。

**链接**：[原文](https://openai.com/index/introducing-gpt-live/)

**分析**：语音不是旁支功能。随着 Work、desktop、computer use 和 Scheduled Tasks 出现，语音会成为 agent 的低摩擦控制层。真正的问题不是语音是否更自然，而是它能否可靠地驱动复杂任务，同时避免误触发、身份冒用和越权操作。

## 趋势观察

### 周末没有新发布，但本周主线已经很明确：agent 产品进入“执行层”竞争

如果只看 7 月 11 日，今天是安静的一天。但把本周一手来源放在一起，主线很清楚：AI 公司正在从模型能力展示转向执行层产品。

OpenAI 的 ChatGPT Work 是最直接的例子。它把 agent 放进应用、文件、浏览器、定时任务和企业治理中。Microsoft 365 Copilot 则证明同一代模型会进入既有办公套件。Google 的 LiteRT.js 和 study notebooks，把 AI 放进浏览器端推理和学习流程。NVIDIA 的工程文章说明，真实 AI workflow 的效率取决于内存、kernel、硬件协同和 pipeline。Anthropic 和 Meta 分别从治理边界与个人 agent 能力补上另外两侧。

因此，2026 年下半年的竞争不只是“谁的模型更聪明”，而是谁能让模型可靠地进入真实工作系统：有权限控制，有审计，有定时运行，有跨应用上下文，有本地与云端分工，也有失败后可恢复的流程。

模型仍是核心，但产品胜负越来越取决于模型周围的执行环境。
