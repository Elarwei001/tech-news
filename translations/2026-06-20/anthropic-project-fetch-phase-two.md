## 核心摘要

Anthropic 在 2025 年曾做过 Project Fetch：让两组非机器人专家员工操作一台现成四足机器人，一组可以使用当时的 Claude，另一组只能依靠互联网和自己的能力。结果显示，Claude 能显著帮助人类更快完成连接设备、编写控制程序和接入传感器等复杂任务。

Phase Two 的问题是：更新后的 Claude 能否不再只是帮助人类，而是更大程度上自己完成这些任务？

Anthropic 使用 Claude Opus 4.7，在 Claude Code 中运行，并把思考强度设为最高。研究人员的角色被限制在接入笔记本、输入初始提示、批准命令和允许模型进入下一阶段。模型尝试完成一组与机器人连接、控制和感知相关的任务。

结果显示，在原始实验中至少一个人类团队完成过的任务上，Opus 4.7 全部至少快 10 倍。在四个所有团队都完成的任务上，Opus 4.7 平均用时 9 分 35 秒；无 Claude 团队用时 361 分钟；Claude 辅助团队用时 181 分钟。按 Anthropic 的计算，Opus 4.7 分别快 37.7 倍和 18.9 倍。

但模型并没有解决机器人学。它仍然难以可靠完成真正的 autonomous fetching，也就是把 beach ball 精确推回起点。这个任务需要闭环控制：持续感知球的位置和误差，理解上一次动作的影响，并调整后续动作。Anthropic 认为，这仍然是当前模型的硬边界。

## 实验做了什么

原始 Project Fetch 要求人类团队完成一串任务：

- 使用厂商提供的控制器操作四足机器人
- 连接机器人的视频和 lidar 传感器
- 编写并运行手动控制程序
- 开发监控机器人空间路径的方法
- 编写检测 beach ball 的程序
- 最后把这些能力组合起来，让机器人自主取回球

Phase Two 不是完全重复原始实验。Anthropic 没有要求 Claude 使用物理控制器，也没有把研究人员使用 Claude 编写的控制器取回球的时间计入评估。研究团队把重点放在模型能通过软件接口完成的任务上，并进行了三轮测试。

这种设计很重要：它测试的不是通用机器人控制能力，而是 agent 是否能快速理解设备接口、写代码、接入传感器和组织控制流程。

## Claude 擅长什么

Claude 的强项集中在“接口理解 + 代码生成 + 调试路径选择”。

在人类团队常常会卡住的地方，比如选择传感器连接方法、确定控制接口、编写程序和修复初始错误，Opus 4.7 能更快找到可行路径。Anthropic 还指出，模型生成的代码量明显更少：原始 Claude 辅助团队写了 10,309 行代码，无 Claude 团队写了 1,136 行代码，而 Opus 4.7 单独完成相关任务只写了 1,045 行代码。

这说明模型的进步不只是“更快打字”。更重要的是，它在方案选择和迭代路径上减少了无效探索。

Anthropic 也强调，这些机器人能力不是专门训练出来的结果，而是通用模型 scaling 后自然外溢出的能力。这一点值得注意，因为它意味着物理工具使用能力可能会随着通用模型继续增强而继续上升。

---

## Claude 卡在哪里

Claude 的明显短板是闭环物理控制。

把机器人移动到球后面、让它把球撞向目标区域，只是任务的一部分。真正困难的是：球会偏离预期；机器人每次动作都会改变环境状态；系统需要实时判断误差，理解误差和前一条命令之间的关系，并调整下一步动作。

人类在练习后可以通过直觉和反馈做到这一点。Claude 在 Phase Two 中可以把机器人移动到大致位置，但对球的控制不够精细，最终没有成功完成 autonomous fetching。

Anthropic 认为，如果给更多时间和更多 scaffolding，当前 Claude 可能可以完成这个最终任务。但这还不是本文已经证明的能力。

## 这意味着什么

Anthropic 的结论可以概括成三步：

1. 早期阶段，模型帮助人类完成复杂任务。
2. 随着模型能力增强，人类开始帮助模型接入环境、授予权限和提供起点。
3. 在某些任务上，模型已经能主要依靠自己完成原来需要人机协作的工作。

Project Fetch Phase Two 显示，这种转变正在从软件环境延伸到物理工具。模型不一定需要从零学会机器人控制，才能产生现实影响。只要它能快速读懂设备文档、连接现成硬件、写控制代码、接入传感器，它就已经能降低很多现实系统的自动化门槛。

这也是风险所在。软件工具可以撤销、回滚、重跑；物理工具会影响真实环境。Anthropic 这次实验仍然保留了人类审批命令，这一点不是细节，而是未来部署的核心安全结构。

## 日报点评

Project Fetch Phase Two 的新闻价值不在“机器狗取球”，而在它展示了 agent 能力扩张的方向。

过去的 coding agent 主要在文件系统、终端、浏览器和 API 里行动。下一阶段，agent 可能进入实验室设备、制造系统、仓储设备、传感器网络和机器人平台。它们未必直接拥有端到端机器人智能，但会先成为“能把设备接起来”的系统集成者。

对企业和研究机构来说，机会是原型速度会大幅提升。非机器人专家可以更快完成设备接入和自动化脚本，领域专家可以把注意力更多放在实验目标和结果解释上。

对安全团队来说，问题是权限边界必须提前设计。未来真正可部署的物理 agent 需要：

- 明确的动作权限
- 人类审批和分级授权
- 完整日志和可回放轨迹
- 环境约束和模拟测试
- 紧急停止机制
- 对高风险动作的实时阻断

这篇文章的现实意义，就是把这些抽象治理问题变得非常具体。
