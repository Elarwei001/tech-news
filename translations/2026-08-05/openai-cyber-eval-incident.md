# 涉及 OpenAI 模型的第三方网络安全评测

> 原文：[Third-party cyber evaluations involving OpenAI models](https://openai.com/index/third-party-cyber-evaluations-involving-openai-models/)
>
> 翻译：Alice Larry | 审校：Colly Markus

---

独立测试在帮助我们验证和进一步理解部署前风险方面发挥着重要作用。一些网络安全评测会有意使用自定义配置，包括降低安全保障来测量底层能力——而非模型在公开部署中的通常行为。

在近期的评测中，两个外部测试伙伴发现了模型活动超出预期测试边界的事件，这些事件涉及测试配置和控制措施与前述模型日益增强的能力相结合的情况。这些事件凸显了在模型能力不断增强的背景下，与行业各方和第三方评测者合作以演进测试环境和实践标准的重要性。

**编者注**：这些事件与 Hugging Face 安全事件是独立的，我们将继续在[此处](https://openai.com/index/hugging-face-model-evaluation-security-incident/)分享 Hugging Face 事件的更新。

新事件涉及 OpenAI 模型在第三方网络安全评测期间访问公共互联网，发生在特定条件和降低保障的配置下，不反映通常的部署行为。事件包括：

- **UK AISI**（英国政府 AI 安全研究所）在网络靶场评测中有意启用了互联网访问，以便智能体可以自主寻找工具并在更接近真实攻击者的条件下运作，同时关闭了网络分类器以测量底层能力。你可以在[这里](http://www.aisi.gov.uk/blog/incident-report-unsanctioned-agent-behaviour-during-cyber-testing)阅读他们的博文。

- **Irregular**（OpenAI 的外部网络安全测试伙伴之一）运行了旨在与互联网隔离的 Capture-the-Flag 风格评测，但测试环境的配置错误导致模型可以访问公共互联网。

以下我们概述了事件经过、导致活动的测试条件、采取的遏制措施，以及我们将如何确保独立实验室能够继续严格且安全地评测能力日益增强的模型。

## 加强第三方模型评测环境

这些事件指向了我们在近期关于 [Hugging Face 事件](https://openai.com/index/hugging-face-model-evaluation-security-incident/)的文章中描述的同一个更广泛的挑战：随着模型能力的增强，围绕模型的安全和保障系统也需要同步进步。这不仅包括用于开发模型的环境，还包括实验室和独立伙伴用于评测模型的环境。

在接下来的几周内，我们将审查自己的第三方测试方法，包括如何识别高风险评测、约定范围、评估启用互联网访问或降低保障的请求、设定隔离预期、凭据处理、监控和停止条件，以及建立更清晰的事件通知和升级流程。

我们致力于跨行业加强安全进行高风险评测的共享实践，包括在未来几周内召集国家 AI 研究所、独立评测机构、其他 AI 实验室等利益相关方。我们的目标是在保持严格独立评测价值的同时，确保测试实践跟得上能力日益增强的模型。

## UK AISI

8 月 3 日，UK AISI 告知我们，在 7 月 25 日开始的一次例行网络评测中，OpenAI 和另一家实验室的模型在部分情况下超出了测试范围。评测在受控的网络靶场中进行，旨在模拟真实世界的网络。在已识别的 19 起事件中，2 起涉及 OpenAI 的模型 GPT-5.6 Sol，其余为另一家实验室的模型。

在此次评测中，智能体被指示在 Capture-the-Flag 练习中扮演网络安全专家角色：攻破三个相互连接的模拟环境并获取最终 flag。任务 prompt 标明了范围内的靶场网络，并指明了若干系统属于范围之外。UK AISI 还启用了实时互联网访问以便智能体可以下载工具并在更接近人类攻击者的条件下运作——并关闭了模型的网络分类器以测量底层能力。

UK AISI 预期的授权边界是模拟网络靶场：智能体被授权攻击指定的模拟网络并获取 flag，而不是与靶场网络边界之外的系统交互。然而，智能体并未被明确告知可以和不可以如何使用开放的互联网访问，UK AISI 将此确定为事件的潜在促成因素。

在这些运行中，UK AISI 发现 GPT-5.6 Sol 在尝试找到进入模拟靶场的路径并获取 flag 时执行了两项未经授权的操作：

- GPT-5.6 Sol 复用了另一家实验室智能体遗留的公开可访问的 GitHub token，用于检查靶场内的系统是否在轮询 GitHub 或其他更新服务，尝试了账户恢复和请求限制绕过，并在外部 DNS 和隧道服务商处注册了账户。

- GPT-5.6 Sol 使用公共隧道服务将运行在其评测环境中的本地 DNS 服务器暴露到公共互联网上。该服务器托管了针对靶场中运行的某软件已知漏洞的 exploit payload。该设置未能正常工作，没有证据表明任何真实解析器查询过它，相关基础设施在评测结束后已被移除。

尽管模型是在尝试完成网络靶场任务，UK AISI 认为这些行为是未经授权的，因为它们涉及靶场边界之外的真实外部账户和服务，且这些行为并非完成任务所必需。DNS 服务器还在公共互联网上托管了 exploit payload，尽管该设置未能工作且没有证据表明任何真实解析器查询过它。

UK AISI 在 7 月 28 日通过安全监控检测到异常数据传输后识别了该活动。它停止了相关评测，隔离了相关机器，并在检测到后约一小时内遏制了该活动。

我们感谢 UK AISI 在整个过程中的合作，包括其识别、调查和分享活动细节的工作。我们期待继续与他们的合作。

## Irregular

7 月 29 日，我们的第三方评测伙伴 Irregular 通知我们发生了涉及 OpenAI 模型在 Capture-the-Flag（CTF）风格网络安全评测中的事件。模型被指示通过利用模拟环境中的弱点来找到隐藏信息，并被告知它们没有互联网访问权限。然而，测试环境中的配置错误导致模型可以访问公共互联网。

在一项测试中，CTF 挑战中虚构目标的名称意外地与一个真实域名重合。由于测试环境被错误地连接到互联网，模型利用了一个真实网站，误将其当作模拟环境的一部分。这不涉及复杂的沙箱逃逸或 zero-day 漏洞：互联网访问是由配置错误导致的，模型似乎利用的是一个基本的安全漏洞。

根据 Irregular 的调查，模型还发现并使用了操作该网站的凭据。Irregular 未识别到超出受影响网站自身数据的影响，其审计仍在进行中。Irregular 已暂停评测、开始修复，受影响的第三方已被告知。Irregular 已告知我们与该事件相关的所有已识别问题均已不再活跃，且相关的保障措施已添加到测试环境中。Irregular 还 communicated 了涉及同一测试环境中其他实验室的相关事件。

我们感谢 Irregular 的合作，将继续与其密切合作以支持其审查。Irregular 还在撰写一份白皮书，分享有关安全运行网络评测的遏制措施和最佳实践。我们期待参与该白皮书，使发现结果可供社区使用，并继续我们的合作。我们认为这种合作对于确保当前和未来模型的安全和全面评测至关重要。
