# OpenAI 与 Hugging Face 携手应对模型评测期间的安全事件

> 原文：[OpenAI and Hugging Face partner to address security incident during model evaluation](https://openai.com/index/hugging-face-model-evaluation-security-incident/)

上周，Hugging Face [披露了一种新型安全事件](https://huggingface.co/blog/security-incident-july-2026)——他们检测并控制了一个攻破其基础设施的 AI agent。随着具备网络攻击能力的模型日益增多，这类事件预计将变得更加普遍。调查后我们确认，该事件是由 OpenAI 模型组合驱动的——包括 GPT-5.6 Sol 和一个更强大的未发布模型，所有模型均已关闭网络安全拒绝策略用于评测目的——在 [ExploitGym](https://arxiv.org/abs/2605.11086) 网络能力基准测试中进行内部测试。

我们认为这是一起涉及最先进网络攻击能力的史无前例的网络安全事件，并正在采取相应行动。我们在现阶段分享初步发现，以帮助防御者了解发生了什么，并帮助校准当前模型已具备的能力。我们将继续与 Hugging Face 一起进行深入调查，并在调查完成后分享更多关于漏洞、事件和发现的细节。

## 事件经过

该事件发生在一次内部评测中，该评测要求模型利用复杂攻击路径进行高级漏洞利用，以量化其网络攻击能力。我们通过在不启用生产分类器的条件下运行该评测来评估最大网络攻击能力——这些分类器通常用于阻止模型从事高风险网络活动。我们的基准测试在高度隔离的环境中运行，网络访问仅限于通过一个内部托管的第三方软件代理（兼作包注册表的缓存代理）安装软件包。

模型组合识别并利用了 OpenAI 研究环境和 Hugging Face 生产基础设施中的漏洞链，直接从 Hugging Face 的生产数据库获取测试答案。所有证据表明，模型高度专注于为 ExploitGym 寻找解决方案，为此不遗余力地追求一个相当狭窄的测试目标。

在沙箱测试环境中运行时，我们的模型消耗了大量推理算力来寻找获取开放互联网访问的方法，以解决评测问题。为获取访问权限，模型识别并利用了包注册表缓存代理中的一个零日漏洞（我们已负责任地向供应商披露）。获得访问权限后，模型在研究测试环境中执行了一系列权限提升和横向移动操作，直到到达一个具有互联网访问权限的节点。

获得互联网访问后，模型推断 Hugging Face 可能托管了 ExploitGym 的模型、数据集和解决方案。基于这一判断，模型搜索并成功找到了获取秘密信息的途径，可用于在评测中作弊。在一个案例中，模型组合了多种攻击向量，包括使用窃取的凭证和零日漏洞，在 Hugging Face 服务器上找到远程代码执行路径。OpenAI 安全团队在内部发现了这一异常活动。

Hugging Face 的安全团队和 agent 在其基础设施上检测并阻止了该活动，当我们两方团队取得联系时，他们已经使用自己的开源模型开始了控制和取证重建。我们正在积极与他们合作继续调查事件。我们感谢 Hugging Face 团队在调查和修复过程中提供的快速而紧密的协作。

## 我们正在采取的行动

- 作为调查的一部分，我们正在以牺牲研究速度为代价实施严格的基础设施配置控制，同时修补漏洞。我们定期向安全与安全委员会通报这些控制措施及其影响。
- 我们正在与 Hugging Face 合作对事件进行取证调查。
- 我们已负责任地披露了在内部托管的第三方软件中发现的零日漏洞，并正与其合作修补。
- 我们已将 Hugging Face 纳入 [trusted access](https://openai.com/index/trusted-access-for-cyber/) 项目，并支持其团队快速使用我们模型的能力来改善防御。
- 我们正在改进和加强对未来训练和评测的保护措施。本周，我们发布了一篇关于 [长程模型时代的安全与对齐改进](https://openai.com/index/safety-alignment-long-horizon-models/) 的博客文章。这些部署保障措施在此次评测中故意未启用，因为评测目标是测试网络漏洞。这一事件表明，我们需要进一步加强模型对齐、评测期间的网络安全保护以及内部测试期间的监控。

## 我们评估高级网络攻击能力的方法

正如我们 [最近](https://openai.com/index/scaling-trusted-access-for-cyber-defense/) 分享的，AI 正在加速漏洞发现和利用的进程。此次事件的主要教训是，模型安全和保障必须跟上快速提升的能力。我们正在加强模型开发中使用的隔离、监控、访问控制和评测实践。

UK AISI 的评测表明，GPT-5.6 Sol 等模型越来越能够长时间维持复杂的多步骤网络操作。此次事件表明，这些理论上的能力确实适用于真实场景。

该事件还清楚表明，高级模型能够在没有源代码访问的情况下发现并利用真实系统中的新型攻击路径。这凸显了高级网络攻击能力必须与更强的保障措施和防御工具同步开发。

我们相信，具备高级网络攻击能力的模型需要帮助安全团队在攻击者之前发现弱点、理解漏洞如何被链接，并以机器速度修复它们。我们正在利用这些能力继续加强基础设施配置和模型评测环境的保护；我们将分享发现和最佳实践。我们鼓励其他防御者 [申请 trusted access](https://openai.com/form/enterprise-trusted-access-for-cyber/) 并立即试用这些模型，将这些能力转化为更好的预防、更快的检测和更有效的事件响应。

> "我们感谢 OpenAI 在此及其他议题上的协作。这一事件可能是同类中的首例，它证明了一个我们一直坚信的观点：AI 安全不会由任何一家公司在秘密中解决。它将在开放中、通过协作、通过让每个防御者都能广泛使用 AI 来解决。"
>
> — Clem Delangue，Hugging Face 联合创始人兼 CEO
