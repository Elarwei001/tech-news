## 概览

OpenAI 在 2026 年 7 月 22 日发布 OpenAI Presence，将其定位为一个面向企业生产环境的 AI agent 产品。文章的核心判断是：企业现在要解决的问题，已经不只是证明 agent 能完成任务，而是如何让 agent 在高价值、真实、持续变化的工作流中保持可靠、可控、可评估。

Presence 面向语音和聊天 agent，目标是帮助企业把 agent 接入客服、销售、内部 IT 服务、保险理赔、银行服务等场景。OpenAI 强调，Presence 不只是模型调用，而是一套把模型推理、企业知识、权限策略、护栏、评估、升级规则和上线后的改进流程组合在一起的产品。

## 产品如何工作

OpenAI 表示，每个 Presence 部署都从一个明确岗位或工作流开始，例如处理账单问题、支持保险理赔，或解决员工 IT 服务请求。agent 只获得完成该任务所需的知识与系统访问权限；企业则定义它能做什么、什么时候需要审批、什么时候必须转交人工。

上线前，团队会用模拟请求、边界场景和高风险场景测试 agent。评估器会检查 agent 是否完成正确结果、是否遵守政策、是否正确使用工具、是否在必要时升级给人类。护栏可以在交互越过企业边界时介入。

上线后，Presence 会继续从生产会话、升级记录和质量信号中发现问题。OpenAI 文中提到，Codex 可以使用 Presence plugin 分析这些信号并建议更新；企业团队再将建议与当前生产版本对比测试，最后批准受控发布。这意味着 Presence 的产品叙事不是“一次配置完成”，而是一个持续调优的 production agent lifecycle。

## 可用场景与企业案例

Presence 目前支持实时语音和聊天体验。OpenAI 给出的例子包括客户支持、外呼销售和高风险内部工作流。一个典型客服 agent 可以理解用户请求、验证身份、查询账户信息、套用公司政策，并在获得授权的情况下执行动作。

OpenAI 称，Presence 已经为自己的英文电话支持渠道提供能力。该渠道可处理开放式请求、验证来电者、使用账户上下文并执行获批动作。OpenAI 表示，Presence 在数周内达到或超过其用于评估一线人工支持质量的基准，现在可在无人介入情况下解决 75% 的来电问题；其 Codex 驱动的改进循环在 10 天内将人工转接减少了 15 个百分点。

OpenAI 还列出三个设计合作方：BBVA 正在探索面向墨西哥日常银行服务的 AI 语音支持；SoftBank 正在测试自然日语客户对话；IAG 正在探索在恶劣天气等高需求事件中提供及时支持。

## 信任、控制与责任

OpenAI 把 Presence 的可信部署拆成上线前、上线中和上线后三层。上线前依赖模拟和评分；上线中依赖政策、标准流程、护栏、批准动作和升级规则；上线后依赖生产信号、Codex 改进建议、测试与受控发布。

这套设计试图解决企业采用 agent 时最现实的问题：模型能力本身不是唯一风险，接入公司系统后的权限边界、政策执行、错误纠正、人工接管和持续维护同样关键。Presence 的文章反复强调企业保留控制权，即使产品会随着模型能力提升和生产反馈持续改进。

## 可获得性

OpenAI 表示，Presence 已面向部分企业客户开放。适合的场景通常具备明确工作流、可评估结果、需要接入公司系统，并且能通过政策和审批定义 agent 的行动边界。

## 行业意义

Presence 的发布标志着 OpenAI 的 agent 战略从“能力展示”进一步进入“生产交付”。过去一年，行业讨论 agent 时经常围绕长上下文、工具调用、规划能力和 benchmark；Presence 把重点拉回企业部署的工程现实：权限最小化、场景限定、模拟评估、上线监控、人工升级和迭代治理。

这也是 OpenAI 与其他 AI 公司竞争方式的变化。模型公司不再只出售“更聪明的模型”，而是在出售可落地的 agent operating model。企业客户真正购买的不是一次回答，而是一个可审计、可改进、可接入业务系统、可承担部分一线流程的智能执行层。

对开发者和企业 AI 团队来说，Presence 的关键启示是：agent 产品化的难点主要在模型之外。知识接入、工具权限、政策表达、评估集、生产日志、升级路径和变更管理，都会决定 agent 能否从 demo 走向可靠业务系统。
