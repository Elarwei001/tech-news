## 概览

OpenAI 发布 GPT-Red，这是一类内部使用的自动化安全红队模型，目标是扩展模型红队测试能力，发现更强、更真实的攻击方式，并把这些攻击样本用于训练生产模型，使后续模型更能抵抗 prompt injection 等攻击。

文章的核心观点是：随着 AI agent 连接浏览器、文件、应用、网页、邮件、代码仓库和工具响应，第三方数据可能携带恶意指令。人工红队仍然重要，但难以产生足够规模和多样性的攻击数据。因此，安全红队本身也需要像模型能力一样规模化。

## 为什么需要自动化红队

OpenAI 指出，红队测试是发现漏洞和提升模型鲁棒性的关键环节，但传统方式存在两个限制：

- 人工设计和执行红队演练耗时，难以跟上模型迭代速度。
- 已有鲁棒性评估已经被最新模型逐步“刷满”，不再能充分区分更强模型之间的安全差异。

GPT-Red 被定位为一种安全自我改进机制：用当前强模型帮助训练和保护未来模型。它不会作为普通产品模型对外提供，而是作为内部攻击者，持续生成更强的 prompt injection、数据外泄和 agent 操纵样本。

## GPT-Red 如何训练

GPT-Red 通过 self-play reinforcement learning 训练。训练过程中，GPT-Red 扮演攻击者，一组不同的 defender LLM 扮演被攻击系统。攻击者获得奖励的条件是诱导 defender 发生有效失败，例如执行 prompt injection、泄露敏感信息、偏离用户任务或执行不该执行的工具动作；防守者则因抵抗攻击并完成原始任务而获得奖励。

这些环境覆盖了现实中 prompt injection 可能出现的位置，包括网页内容、本地文件、邮件正文、工具返回结果、代码仓库和其他第三方输入。每个环境都定义了攻击者能控制什么、什么算成功攻击。

训练完成后，GPT-Red 能在大量场景中找到此前模型未能抵抗的攻击。OpenAI 将这些攻击样本直接纳入生产模型训练流程，用于提升 GPT-5.6 等模型的鲁棒性。

## 能力与案例

OpenAI 将 GPT-Red 与人工红队在一个复现的间接 prompt injection 竞技环境中比较。GPT-Red 在新场景中对 GPT-5.1 的攻击成功率达到 84%，而人工红队为 13%。这说明自动化红队不只是复现训练集攻击，也能迁移到未见过的安全环境。

文章还给出两个现实 agent 案例：

- 在一个办公室自动售货机 agent 场景中，GPT-Red 先在模拟环境里迭代攻击，再迁移到生产 agent，使其错误地修改商品价格、下单高价商品并取消其他用户订单。
- 在 Codex CLI agent 场景中，GPT-Red 针对 10 个保留的数据外泄任务攻击基于 GPT-5.4 mini 的 agent，相比普通 GPT-5.5 prompt baseline 更有效，也更省 token。

这些案例说明，agent 安全问题不是抽象的聊天对齐问题，而是涉及工具调用、权限、交易、文件、浏览器和真实世界状态变化的系统安全问题。

## 对 GPT-5.6 的影响

OpenAI 表示，过去六个月中，它训练了逐步增强的 GPT-Red 前身，并将其生成的攻击样本用于后续生产模型训练。随着这条流程推进，新模型对 prompt injection 的抵抗力持续提高。

几个关键结果包括：

- GPT-5.6 Sol 在 OpenAI 最困难的直接 prompt injection benchmark 上，失败次数比四个月前最强生产模型少 6 倍。
- 早期 GPT-Red 发现的 Fake Chain-of-Thought 攻击，在 GPT-5.1 上成功率曾超过 95%，而在 GPT-5.6 Sol 上降至 10% 以下。
- 在 GPT-Red 的一组直接 prompt injection 测试中，GPT-5.6 Sol 的失败率仅为 0.05%。

OpenAI 同时强调，它评估了通用能力和过度拒绝风险，认为鲁棒性提升不是靠模型“少做事”或拒绝更多正常请求换来的，而是更好地区分恶意指令与合法任务。

## 安全边界

GPT-Red 是内部模型。OpenAI 不将它作为普通模型部署，以避免把专门训练出的攻击能力交给外部攻击者。它的用途是发现漏洞、生成 adversarial training 数据、配合人工和第三方红队、分层防护以及实时监控。

这也是文章最重要的治理含义：安全能力本身正在被工业化。未来模型不只会通过更多人工审核变安全，而会通过自动化攻击者、自动化防守者、连续评估、生产前演练和训练闭环来持续改进。

## 译读总结

GPT-Red 的行业意义在于，它把“模型安全”从发布前检查变成持续训练系统。Agent 时代的风险来自模型与工具、数据、网页、文件和现实动作的组合；只靠人工红队很难覆盖所有边界。OpenAI 的方案是让红队也成为可扩展模型能力，并把攻击发现直接转化为训练信号。

这条路线有明显价值，也有明显张力：自动化红队越强，越能帮助生产模型抵御攻击；但这种攻击模型也必须被严格隔离。长期看，AI 安全竞争会越来越像网络安全竞争：攻防双方都自动化，关键在于谁能更快把新攻击转化为防御和评估。
