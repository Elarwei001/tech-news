# 《Agentic coding and persistent returns to expertise》中文译读

> 原文：Anthropic Research, 2026-06-16  
> 链接：https://www.anthropic.com/research/claude-code-expertise  
> 说明：本文为版权合规的中文译读，按原文结构完整覆盖主要论点、数据、章节和结论，不逐字搬运全文。

## 关键发现

Anthropic 在这份报告中分析了约 40 万个 Claude Code 交互式会话，时间跨度为 2025 年 10 月至 2026 年 4 月。研究采用隐私保护方法，关注三件事：人们把 Claude Code 用在什么任务上，人类与 AI 如何分工，以及不同专业背景的用户是否能成功完成任务。

报告的核心结论是：agentic coding 没有让人的专业知识失去价值。相反，具备领域知识的人往往能让 Claude 完成更多、更有价值的工作。人类通常做规划决策，Claude 更多承担执行决策。随着时间推移，用户从单纯修 bug 转向更端到端的工作，包括部署运行软件、分析数据和撰写非代码文档。

Anthropic 还估算，典型任务的相对价值在七个月内平均上升约 25%。在会话中，非软件职业用户完成代码任务的成功率接近软件工程师，但领域专家仍明显优于新手。

## 引言

报告从一个问题出发：随着 coding agent 快速普及，没有传统编程背景的人能否成功指挥 agent 完成复杂技术工作？这些工具对软件职业和知识工作意味着什么？

Anthropic 的数据来自约 23.5 万名用户的 Claude Code 会话。研究覆盖 Claude Code 的命令行界面、Claude.ai 和桌面应用，但排除了第三方 IDE、SDK 和 headless 模式等非交互式用法。报告强调，这些交互式会话可能预示更广泛知识工作的未来，因为 agent 正在进入越来越多非纯编码场景。

作者认为，当前分工清晰：人类决定要做什么、为什么做、怎样算完成；Claude 决定如何改文件、写代码、运行命令和执行细节。专业知识的价值并未消失，因为用户越理解任务领域，越能有效指挥 agent。

## 分工：人做规划，Claude 做执行

研究把 Claude Code 会话分为九类工作模式。其中四类直接涉及代码：创建新功能、修复问题、测试代码、编排其他 agent 或自动化流程。另有一类是操作软件，比如部署、配置、运行管线和监控系统。两类偏向理解和规划：理解现有系统、规划变更。最后两类则更偏向数据分析和文档沟通。

统计显示，约 56% 的会话属于写代码、修复、测试或编排代码；17% 是软件运维；14% 是规划或理解系统；13% 是数据分析或沟通写作。

在决策层面，Anthropic 用分类器识别会话中的重要决策，并区分规划决策与执行决策。平均来看，人类做出约 70% 的规划决策，但只做出约 20% 的执行决策。也就是说，人类更像产品负责人、领域专家或审稿人，Claude 更像执行工程师。

在动作层面，一个典型会话大约有四轮人机往返。每次用户发出指令后，Claude 平均会执行约 10 个动作，包括读取文件、修改代码、运行命令和输出较长说明；少数会话中，Claude 每轮会执行上百个动作。

## 用户是谁，任务是否成功

报告分析了不同职业背景用户的任务成功率。成功的定义不是简单看对话是否结束，而是寻找可验证证据，例如测试通过、代码提交、文件产生或任务状态明确完成。

一个关键发现是：在产生代码的会话中，主要职业类别的成功率都接近软件工程师。这说明 coding agent 正在降低编程背景对完成技术任务的门槛。

但这并不意味着专业知识不重要。Anthropic 根据会话内容推断用户在任务领域的专业程度，发现专业程度越高，成功率越高。专家级会话的验证成功率超过新手两倍。当会话遇到麻烦时，新手更容易放弃，而中级和专家用户更能纠正方向、补充约束并恢复进展。

报告的解释是：编程能力的相对门槛下降了，但任务领域的理解仍然关键。用户越清楚问题是什么、正确结果是什么、哪些错误可以接受，就越能让 agent 产出有价值的工作。

## 使用方式随时间变化

在 2025 年 10 月到 2026 年 4 月期间，Claude Code 的使用模式发生变化。调试类会话占比下降近一半，而端到端任务增加，包括部署运行代码、分析数据、撰写报告和制作文档。

Anthropic 认为，这反映出 agent 能力和用户信任的共同变化。早期用户可能更多把工具当作修 bug 助手；随着模型能力提升和使用习惯形成，用户开始把更完整、更开放的任务交给 Claude。

报告还尝试估算任务的经济价值。方法是把 Claude Code 会话与自由职业市场上的岗位描述进行模糊匹配，关注相对变化而非绝对金额。结果显示，典型任务价值在多数类别中上升，平均约 25%。

## 展望

Anthropic 的结论是，agentic coding 正在改变技能的回报结构。代码实现能力的一部分正在被 agent 吸收，但领域判断、问题定义和结果审查仍然重要，甚至可能更重要。

如果这种趋势延续，软件生产可能会越来越多地成为各行业日常工作的一部分，而不是单一软件职业的专属产物。懂业务、懂科学、懂流程、懂评估的人，将更容易把自己的专业知识转化为可运行系统。

但报告也保留了谨慎态度。它无法判断会话产物是否真的进入生产环境，也无法衡量实际经济成果。所有分类都依赖模型读取会话，验证仍有困难。非交互式 Claude Code 用法也没有纳入分析，而这部分可能代表大量自动化和流水线场景。

Anthropic 表示，未来需要继续更新这些指标，观察随着模型、用户和人机分工变化，专业知识的回报是否会下降。如果未来模型开始承担更多本属于人类的判断，那么 agent 的收益可能会进一步扩展到更广泛人群。
