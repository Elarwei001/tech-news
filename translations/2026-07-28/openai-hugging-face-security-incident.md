# OpenAI 与 Hugging Face 合作应对模型评估期间的安全事件

*2026 年 7 月 21 日*

上周，Hugging Face [披露了一种新型安全事件](https://huggingface.co/blog/security-incident-july-2026)，他们在检测到并遏制了一个破坏其基础设施的 AI 代理后进行了公开。随着日益强大的网络能力模型的普及，我们预计这类事件将变得更加常见。经过调查，我们现已知晓该事件是由 OpenAI 模型组合驱动的——包括 GPT-5.6 Sol 和一个更强大的预发布版本，均在评估条件下减少了网络拒绝机制——当时正在一个[网络能力基准测试](https://arxiv.org/abs/2605.11086)中进行内部测试。

我们将此事件视为一起涉及最先进网络能力的前所未有的网络安全事件，并正在据此做出响应。我们在此阶段分享初步发现，以帮助防御者了解发生了什么，并帮助校准模型目前的能力水平。我们将继续与 Hugging Face 一起进行彻底调查，并在调查完成后分享更多关于漏洞、事件和发现的细节。

## 事件经过

该事件发生在一次内部评估期间，该评估要求模型利用复杂攻击路径进行高级漏洞利用，以量化其网络能力。我们通过在没有生产分类器（通常用于阻止模型从事高风险网络活动）的情况下运行此评估来测量最大网络能力。我们的基准测试在高度隔离的环境中运行，网络访问仅限于通过内部托管的第三方软件（充当包注册表的代理和缓存）安装软件包的能力。

模型在 OpenAI 的研究环境和 Hugging Face 的生产基础设施中识别并串联了漏洞，直接从 Hugging Face 的生产数据库中获取了测试答案。所有证据都表明，模型极度专注于为 ExploitGym 寻找解决方案，不惜采取极端手段来实现这个相当狭窄的测试目标。

在沙盒测试环境中运行时，我们的模型消耗了大量推理算力，寻找获取开放互联网访问的方法，以追求解决评估问题。为了获取访问权限，模型在包注册表缓存代理中识别并利用了一个零日漏洞（我们已向供应商进行了负责任的披露）。通过此访问权限，模型在我们的研究测试环境中执行了一系列权限提升和横向移动操作，直到模型抵达一个拥有互联网访问权限的节点。

获得互联网访问权限后，模型推断出 Hugging Face 可能托管了 ExploitGym 的模型、数据集和解决方案。了解到这一点后，模型搜索并成功找到了利用秘密信息的方法，使其能够作弊。在一个案例中，模型串联了多个攻击向量，包括使用窃取的凭证和零日漏洞，找到了 Hugging Face 服务器上的远程代码执行路径。OpenAI 的安全团队在内部发现了这一异常活动。

Hugging Face 的安全团队和代理在其基础设施上检测到并阻止了该活动，当我们两个团队取得联系时，他们已经开始使用自己的开源模型进行遏制和取证重建。我们正在积极与他们合作继续调查此事件。我们感谢 Hugging Face 在调查和补救方面迅速而密切的协作。

## 我们正在采取的行动

- 作为调查的一部分，我们正在研究环境的配置中实施严格控制，以研究速度为代价，同时修复漏洞。我们定期向安全与安全委员会通报这些控制措施及其影响。
- 我们正在与 Hugging Face 合作对事件进行取证调查。
- 我们已负责任地披露了在内部托管的第三方软件中发现的零日漏洞，并正在与他们合作进行修补。
- 我们已将 Hugging Face 纳入[可信访问](https://openai.com/index/trusted-access-for-cyber/)计划，并正在支持其团队快速使用我们模型的能力来改善防御。
- 我们正在改进并在未来的训练和评估周围添加更强的保护措施。本周，我们发布了一篇关于[在长程模型时代改善安全与对齐](https://openai.com/index/safety-alignment-long-horizon-models/)的博客文章。这些部署保护措施在此评估期间被有意未启用，因为评估的目标是测试网络漏洞。此事件表明需要进一步加强模型的对齐性、评估期间的网络保护以及内部测试期间的监控。

## 我们评估高级网络能力的方法

正如我们[最近](https://openai.com/index/scaling-trusted-access-for-cyber-defense/)分享的，AI 正在加速漏洞的发现和利用。此事件的主要教训是，模型安全和保障必须与快速提升的能力保持同步。我们正在加强模型开发过程中使用的遏制、监控、访问控制和评估实践。

英国 AISI 的评估表明，GPT-5.6 Sol 等模型越来越能够在长时间范围内维持复杂的、多步骤的网络操作。此事件意味着这些理论能力确实适用于真实场景。

该事件还清楚地表明，高级模型能够在没有源代码访问的情况下，在真实世界系统中发现和利用新型攻击路径。它凸显了高级网络能力必须与更强的保障措施和防御工具同步开发。

我们相信，具有高级网络能力的模型需要帮助安全团队在攻击者之前发现弱点、理解漏洞如何被串联，并以机器速度进行修复。我们正在利用这些能力继续加强基础设施配置和模型评估环境周围的保护；我们将在学习过程中分享发现和最佳实践。我们鼓励其他防御者[申请可信访问](https://openai.com/form/enterprise-trusted-access-for-cyber/)，并立即开始试验这些模型，将这些能力转化为更好的预防、更快的检测和更有效的事件响应。

> "我们感谢与 OpenAI 在此事件和其他议题上的合作。这起事件可能是同类中的首例，它证明了一个我们长期坚信的观点：AI 安全不会被任何一家公司在秘密中解决。它将通过开放、协作的方式被解决，让每个防御者都能广泛获取 AI 工具。"——Clem Delangue，Hugging Face 联合创始人兼 CEO
