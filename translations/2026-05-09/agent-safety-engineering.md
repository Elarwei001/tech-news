# Running Codex safely at OpenAI：在 OpenAI 安全运行 Codex

> 原文：https://openai.com/index/running-codex-safely/
>
> 译注：根据官方页面可抓取正文翻译整理。保留 Codex、sandbox、telemetry、approval 等工程术语。

## 正文翻译

随着 AI 系统能力增强，它们越来越多地代表用户行动。coding agent 可以自主查看代码仓库、运行命令，并和开发工具交互。这些任务过去通常需要人类直接执行。

OpenAI 表示，在设计 Codex 时，能力和组织部署所需的控制机制是一起考虑的。安全团队需要知道 agent 能访问什么、什么时候需要人类批准、它能和哪些系统交互，以及有哪些 telemetry 可以解释它做过什么。

在 OpenAI 内部部署 Codex 时，目标很清楚：把 agent 保持在明确的技术边界内；让开发者在低风险动作上保持速度；让高风险动作显式化；同时保留 agent-native telemetry，以便理解和审计 agent 的行为。

实践上，这意味着需要托管配置、受限执行环境、审批策略、命令审计，以及对 agent 行为的可观测性。Codex 不是被当作一个可以无限制执行命令的模型，而是被放在一组工程边界中运行。

文章强调，coding agent 的风险并不抽象。它会读取文件、修改代码、运行测试、调用工具，甚至可能触碰凭证或部署流程。因此，安全设计不能只依赖模型“应该知道不要做什么”。系统层必须提供限制、记录和恢复能力。

OpenAI 的做法体现了一种分层安全观：模型负责理解任务和生成行动计划；运行环境负责限制行动范围；审批机制负责把高风险步骤交还给人；telemetry 负责在事后解释发生了什么。

## 为什么重要

这篇文章把 agent 安全从原则拉回工程现实。一个真正可部署的 coding agent，不能只展示会写代码，还必须能被组织治理。企业采用 agent 时，最关心的往往不是 demo 是否惊艳，而是权限、审计、责任和故障恢复是否清楚。

这也解释了为什么 5 月 9 日适合做趋势日：OpenAI 的 Codex 安全部署、Anthropic 的模型理由训练、NVIDIA 的工具调用基础设施，指向同一件事，agent 安全正在工程化。

## 译后备注

- telemetry 译为“遥测/行为记录”，这里指帮助审计 agent 行为的数据。
- approval 指人类审批机制，不是模型自我确认。
